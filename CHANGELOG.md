## [1.0.0] - 2026-09-04

The first stable release. v1.0.0 makes the self-hosted platform dependable — real migrations, a supervised single image, a rebuilt analytics pipeline, a hardened API, a rewritten player — and adds an **optional** paid mode (`HOVOD_CLOUD=true`) that powers [Hovod Cloud](https://hovod.dev).

**Self-hosting stays free, unlimited and unmetered.** Nothing in the cloud code path runs unless you set `HOVOD_CLOUD=true`.

This release contains **breaking changes**; read [Upgrading from 0.x](#upgrading-from-0x) before pulling the image.

### Added

#### Database & operations

- **Versioned SQL migrations** (`packages/db/migrations/NNNN_name.sql`) applied at API boot by `runMigrations()` from `@hovod/db`: recorded in `schema_migrations`, serialised across replicas with `GET_LOCK('hovod_migrations', 120)`, statements split on `-- >statement-breakpoint`. A failing statement throws `MigrationError` (file, statement index, MySQL error) and aborts the boot instead of leaving a half-applied schema. Existing installs are detected and baselined by a one-time `legacyRepair()` — no data loss, no manual step.
- **One image, three roles** — `HOVOD_ROLE=allinone|api|worker` selects which services start. `api` and `worker` never launch the embedded MariaDB/Redis and exit immediately (code 78) listing what is missing.
- **s6-overlay v3 supervision**: ordered start (mariadb-init → mariadb/redis → worker/api), readiness probes that actually log in / `PING`, crash restart, ordered shutdown on `docker stop`. API and worker run as the non-root `hovod` user.
- **`hovod-backup` / `hovod-restore`** in the image (`/data/backups`, keeps 7, `-` streams to stdout/stdin) plus a documented restore drill.
- **`hovod-cli`** (`hovod-cli reset-password <email>`) for self-hosts with no mail provider.
- Role-aware `HEALTHCHECK`, `/health/ready` returning 503 when the database is unreachable, and a public `GET /v1/config` reporting server capabilities.
- **CI** (`ci.yml`): typecheck, build, image build and a `docker run` smoke test (ready probe, signup, asset creation, backup, worker kill/restart, graceful stop). **Release** (`release.yml`): native amd64 + arm64 runners, digest push, multi-arch manifests to Docker Hub and GHCR.
- `docker-compose.prod.yml` showing the split deployment (2 API replicas, 1 worker, external DB/Redis/S3).

#### Analytics

- **`playback_sessions`** — one row per playback session, upserted from the player's event batches. Every metric is computed from that table for the requested period; there is no background aggregation and no separate lifetime counter.
- `POST /v1/analytics/events` (public, own 300/min/IP bucket): resolves `playbackId` → asset/org server-side, validates each event independently and answers `202 { accepted, rejected }`.
- `GET /v1/assets/:id/analytics` and `GET /v1/analytics/overview` with `period=7d|30d|90d|all`: views, unique viewers, watch time, average watched, completion rate, retention deciles, engagement score, hourly/daily series, peak hour, devices, quality distribution, buffer ratio, errors, top referrers and top assets.
- Player instrumentation: `view_start` after the first `timeupdate` past 1 s, 10 s heartbeats carrying real wall-clock watch time, `sendBeacon` flush on `visibilitychange`/`pagehide`, session id in `sessionStorage` (new one after 30 min idle), viewer id in `localStorage`, owner previews excluded.
- `ANALYTICS_RETENTION_DAYS` (default 400) with a daily batched cleanup job.

#### Player & embed

- Root is an aspect-ratio box derived from the video's own dimensions (16/9 fallback) with `overflow-hidden` — no more scrollbars in an iframe for 4:3, 9:16 or 21:9 content, and correct fullscreen.
- Custom subtitle overlay sized by container query (`clamp(14px, 4.4cqh, 34px)`) instead of `::cue`, positioned above the controls.
- hls.js tuning plus fatal-error recovery (network retries with backoff, `recoverMediaError`, `swapAudioCodec`) and a Retry button.
- Keyboard shortcuts (`Space`/`K`, `←`/`→`, `J`/`L`, `↑`/`↓`, `M`, `F`, `C`, `0`–`9`), touch behaviour (first tap reveals controls), a real focusable progress slider, `preload="metadata"`, hours in `formatTime`.
- **Embed query parameters**: `autoplay`, `muted`, `loop`, `t`, `cc`, `color`, `title` — documented in [docs/api-reference.md](docs/api-reference.md#embed-parameters) and generated by the Share dialog with the asset's real aspect ratio.
- **A standalone Vite entry for `/embed`**: third-party pages no longer download the dashboard bundle. `/watch` and `/embed` are lazy-loaded in the SPA and no longer issue an authenticated `/v1/settings` call.

#### API

- **`GET /v1/assets` is paginated**: keyset pagination on `(created_at DESC, id DESC)` with an opaque `cursor`, `limit` (default 50, max 200), `q` search (LIKE wildcards escaped), `status` / `sourceType` filters, and `fields=full` for the heavy columns. Based on the work of @leuwenn in #3.
- **S3 multipart upload**: `POST /v1/assets/:id/multipart/{create,part-url,complete,abort}` with a client that uses 16 MB parts, 3 in parallel, per-part retry with a fresh presigned URL, resume from `sessionStorage` and a `beforeunload` guard.
- **Invitations**: `POST /v1/orgs/:orgId/members/invite`, `GET`/`DELETE /v1/orgs/:orgId/invitations[/:id]`, public `GET /v1/invitations/:token` and `POST /v1/invitations/:token/accept`.
- **Password reset**: `POST /v1/auth/forgot-password` (always 200, no account enumeration) and `POST /v1/auth/reset-password` (one-time, 1 hour, invalidates other sessions), with a CLI fallback.
- `POST /v1/auth/logout-all`, `GET /v1/orgs/:orgId/usage`, `PATCH /v1/orgs/:orgId` (name, webhook URL).
- API keys gain `scopes` (`read` / `read`+`write`), `expires_at` and `created_by`.
- Transactional email through the Resend REST API (`RESEND_API_KEY`, `EMAIL_FROM`): invitation, password reset, welcome, payment failed, subscription canceled. Optional in self-host — without it invitations are link-only and password resets come from the CLI.

#### Worker

- 1440p, 2160p (4K) and 4320p (8K) rungs, filtered to the source's short side so nothing is upscaled.
- HDR (PQ/HLG) → SDR BT.709 tone-mapping, enabled only when the runtime FFmpeg provides `zscale`/`tonemap` (probed once at boot).
- Real probed output dimensions, codecs, measured `AVERAGE-BANDWIDTH` and `FRAME-RATE` in `master.m3u8` and in the `renditions` rows; `CODECS` advertises audio only when an audio stream was mapped.
- Keyframes aligned to the 6 s segment boundary, `-preset medium` on the low rungs, `#EXT-X-INDEPENDENT-SEGMENTS`.
- Startup reconciliation: assets stuck in `queued`/`processing` with no live queue job are flagged "Processing was interrupted — click Retry", with a Retry button in the dashboard.
- `WORK_DIR` scratch directories with a free-space check (~3× the source) and a 24 h stale sweep at boot; cgroup v2 CPU/memory limits honoured.
- FFmpeg stderr is captured into `error_message` — no more bare "exited with code 234".
- Whisper audio is split into 10-minute chunks and merged with offset timestamps, lifting the ~52-minute ceiling imposed by the 25 MB request limit.
- `S3_PUBLIC_ACL=false` for Cloudflare R2 and any bucket with ACLs disabled.

#### Dashboard

- **TanStack Query** data layer: explicit loading and error states everywhere, polling only while an asset is in a transitional status and never in a hidden tab, centralised 401 → `/login?from=`.
- Accessible `<Modal>` primitive (role, focus trap, Escape, scroll lock) used by every dialog.
- Thumbnail editor, retry-processing action, debounced search with "Load more", inline comment errors, mobile sidebar closing on navigation.
- eslint flat config (`typescript-eslint` + `react-hooks`) wired to `npm run lint -w @hovod/dashboard`; route-level code splitting.

#### Hovod Cloud (optional, `HOVOD_CLOUD=true`)

Documented in full in [docs/cloud.md](docs/cloud.md). None of it runs in self-host.

- **Paid-only signup**: `POST /v1/auth/signup { …, plan }` creates the user, a *pending* organization and a Stripe Checkout in one transaction, returning `{ token, checkoutUrl }`. Additional organizations (`POST /v1/orgs { name, plan }`) start their own Checkout.
- **Stripe is the source of truth**: a single `syncSubscription()` mirrors status, plan, price, period end, cancel-at-period-end, grace deadline and activation into `organizations` from three paths — the Checkout return (`POST /v1/billing/sync`), the signature-verified webhook (`POST /v1/billing/webhook`, deduplicated through `stripe_events`) and a nightly Redis-locked reconcile. Plus `POST /v1/billing/checkout` and `POST /v1/billing/portal`.
- **Entitlements**: every org is `active`, `grace` (7 days after the first `past_due`), `readonly` or `pending`. Read-only and pending orgs may still `GET`, but every mutating `/v1` request answers **402** `{ error, code: 'subscription_required', status }`.
- **Plan limits** (Pro / Business): monthly encoding minutes, AI minutes, storage, API keys, members and per-minute rate limit — pre-checked cheaply by the API (`402` with `storage_limit`, `encoding_limit`, `api_keys_limit`, `members_limit`) and authoritatively by the worker once the source duration is known.
- **Usage in MySQL**: `usage_monthly` (UTC month, seconds) written by the worker, `assets.storage_bytes` = source + renditions + thumbnails + AI outputs. Exposed by `GET /v1/auth/me` and `GET /v1/orgs/:id/usage`.
- Dashboard: plan selector at signup, full-page paywall for pending orgs, grace/read-only banners, a Subscription card with usage bars and portal buttons, `?checkout=success` handling that polls until the webhook lands.

#### Documentation

- New [docs/cloud.md](docs/cloud.md) (operator guide: Stripe setup, webhooks, dunning, R2/CDN, go-live checklist) and [docs/self-host-vs-cloud.md](docs/self-host-vs-cloud.md).
- `docs/api-reference.md` covers every endpoint; `docs/configuration.md` matches both `env.ts` schemas; `scripts/check-env-docs.mjs` fails the build when a variable is documented nowhere.

### Changed

- **BREAKING — JWT payload is now `{ sub, org, tv }`** and access tokens live **24 hours** (was 7 days). `tier` is gone from the token; entitlements are read from the database behind a 30 s cache, so a customer who upgrades is not stuck with stale rights until they sign in again. `tv` is `users.token_version`: changing the password, resetting it or calling `POST /v1/auth/logout-all` invalidates every token issued earlier. **Every existing session is signed out by the upgrade.**
- **BREAKING — `GET /v1/assets` returns one page**, not the whole library. The response gains a `pagination` block (`limit`, `hasMore`, `nextCursor`, `total`) and the heavy columns (`description`, `metadata`, `customMetadata`, `publicSettings`) are omitted unless `fields=full` is passed. Clients that read `data` still work but must follow `nextCursor` to see everything.
- **BREAKING — analytics tables replaced.** `analytics_events`, `analytics_daily` and `analytics_asset_stats` are dropped by migration `0002` after their history is folded into `playback_sessions` per session. **Historical view counts are recomputed** from that import, so numbers move on upgrade: previous totals were inflated (every playback metadata fetch counted as a view, on top of the player's own event) and watch time was estimated. The new numbers are lower and correct.
- **BREAKING — per-app Dockerfiles removed.** `apps/api/Dockerfile`, `apps/worker/Dockerfile` and `apps/dashboard/Dockerfile` are gone, and with them the separate `vite preview` dashboard container: the API serves the built dashboard. Build the root `Dockerfile` and pick a role with `HOVOD_ROLE`.
- **BREAKING — `DASHBOARD_URL` is deprecated in favour of `APP_URL`.** `APP_URL` is the public base URL used for embed and share links, invitation and password-reset emails, and billing return URLs. `DASHBOARD_URL` is still honoured when `APP_URL` is unset and will be removed in a future release.
- **BREAKING — Stripe variables renamed**: `STRIPE_PRO_PRICE_ID` → `STRIPE_PRICE_PRO`, `STRIPE_BUSINESS_PRICE_ID` → `STRIPE_PRICE_BUSINESS`. With `HOVOD_CLOUD=true` these, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `RESEND_API_KEY` and `EMAIL_FROM` are validated as a group: the API refuses to boot half-configured.
- **BREAKING — one `download.mp4` per asset** instead of one per rendition, remuxed from the highest rung. `GET /v1/assets/:id/download?quality=…` still answers: it looks for the legacy per-rendition file first and falls back to the single file. Assets encoded by 0.x keep their old files until they are re-encoded.
- Organization `tier` is replaced by `plan` + `subscription_status` (migration `0004`: `pro`/`business` → `plan`, `free` → `NULL`, column dropped).
- The MySQL pool is pinned to UTC (`timezone: 'Z'` + `SET time_zone` per connection), so date bucketing no longer depends on the server's session time zone.
- `POST /v1/assets/:id/process` is accepted only from `uploaded` or `error` (409 otherwise) and uses the deterministic BullMQ job id `transcode-<assetId>`; the transcode queue gets `attempts: 2` with exponential backoff and retention limits.
- `renditions` gains `UNIQUE (asset_id, quality)` (duplicates removed by migration `0003`), and `file_size_bytes` is `BIGINT`.
- `docker-compose.override.yml` no longer overwrites `DATABASE_URL` / `S3_ENDPOINT`, binds infrastructure ports to `127.0.0.1` and is marked development-only.
- Documentation restructured: README rewritten for v1, `DOCKER.md` rewritten around the supervised image, `CLAUDE.md` matches the real architecture.

### Fixed

- **Views were counted twice** (a server-side view on every playback metadata fetch plus the player's own) and counted on videos nobody watched; owner previews were counted too.
- **Retention curves were flat and "avg watched" absurd**: the unescaped `current_time` column was parsed by MySQL as the `CURRENT_TIME()` function.
- **The hourly aggregation `REPLACE` destroyed ~55 minutes of every hour**, and lifetime totals shrank every day as the 30-day event purge ate the history the "all time" tiles were reading.
- **Unique viewers were summed across buckets** instead of counted distinctly.
- Mobile sessions were lost (only `beforeunload` was handled), a reload started a new session, and a single `NaN` duration dropped a whole ingestion batch.
- **`GET /v1/assets/:id/playback` was not scoped to the organization** — any authenticated tenant could resolve another tenant's playback id from a guessed asset id (IDOR). `findAssetOrFail()` now requires an org id; a foreign asset is a 404.
- **Failed authentication was never rate-limited**: `@fastify/rate-limit` installs a per-route `onRequest` hook, which Fastify runs *after* instance-level hooks. The limiters are now installed by hand so the order is per-IP → auth → per-org, and rejected credentials have their own 10/min/IP budget.
- **Any member could mint a permanent org-wide API key.** Creating and revoking keys, and renaming an org, now require owner or admin; removing a member revokes the keys they created; expired keys are rejected.
- **SSRF via URL import**: the shared guard rejects non-http(s) URLs, credentials in the URL, unusual ports and any address resolving to a private, loopback, link-local, multicast or unique-local range (IPv4, IPv6 and v4-mapped alike) — re-checked on every redirect the worker follows.
- The iframe embed had no subtitles, showed scrollbars for any ratio that was not exactly 16:9, and rendered captions far too small.
- A network blip during playback ended in a permanent "This video cannot be loaded".
- An interrupted direct upload left a truncated `input.mp4` that the worker happily tried to transcode; the partial file is now removed and the asset returns to `created` with a retry hint.
- The dashboard rendered a failed request as an empty library / empty organization / no API keys; a reopened settings modal showed a stale draft; a comment box cleared itself before the API accepted the comment.
- `VideoDetailPage` mutated query state while sorting renditions.
- Transcripts and chapter lists larger than the 1 MB JSON limit were rejected — those two routes now accept 10 MB.

### Removed

- **Organization tiers**: `ORG_TIER`, `TIER_LIMITS`, `UNLIMITED_TIER_LIMITS`, the `tier` column, `request.orgTier` and the free-tier asset cap. Self-host has no tier; cloud has `plan` + `subscription_status`.
- **`apps/api/src/services/metering.ts`** and the Redis-based usage counters — usage is `usage_monthly` in MySQL, written by the worker. There is no Stripe Billing Meters integration and delivery/bandwidth is not metered at all.
- `GET /v1/billing/subscription` (use `GET /v1/auth/me` → `org` / `GET /v1/orgs/:id/usage`), and `POST /v1/orgs/:orgId/members` (adding an existing user by email) — replaced by invitations.
- The raw-SQL schema bootstrap in `apps/api/src/db.ts` (`CREATE TABLE IF NOT EXISTS` plus a list of swallowed `ALTER`s) — replaced by the migration runner.
- `apps/api/Dockerfile`, `apps/worker/Dockerfile`, `apps/dashboard/Dockerfile`, the `dashboard` compose service and `.github/workflows/docker.yml`.
- The unused `ImportForm` dashboard component and the legacy hourly/daily analytics aggregation jobs (their schedulers are removed from Redis at boot).

### Security

- Multi-tenant isolation fixed on `GET /v1/assets/:id/playback` (IDOR).
- Failed-credential rate limiting, dedicated 10/min/IP budgets on login and signup, 5/min/IP on password-reset endpoints, a per-plan (or 600/min self-host) per-organization budget.
- Session revocation through `users.token_version`; access tokens shortened to 24 hours.
- API keys peppered with a separate `API_KEY_SECRET` (falling back to `JWT_SECRET`, so existing keys keep working) so the JWT secret can be rotated independently; scopes and expiry enforced; keys revoked when their creator is removed.
- SSRF guard on URL import **and** on organization webhook URLs (https required there).
- A real Content-Security-Policy on the dashboard, with `frame-ancestors *` restricted to `/embed/*` and `/watch/*`; `CORS_ORIGIN='*'` logs a warning at boot in production.
- Analytics ingestion no longer trusts a client-supplied `assetId`, and unknown or not-ready playback ids are rejected.
- Password reset tokens are single-use, hashed at rest, expire in one hour and invalidate other sessions; `forgot-password` answers identically whether or not the account exists.
- Accepting an invitation for an address that already has an account requires that account's session or password — possessing the link is not enough.

### Upgrading from 0.x

1. **Back up first.** `docker exec hovod hovod-backup` (or your provider's snapshot for an external database). Migration `0002` drops the legacy analytics tables after importing them.
2. **Pull and recreate with the same `/data` volume.** Migrations run automatically at API startup; on an existing install the baseline is applied without re-executing.
3. **Everyone is signed out.** The JWT payload changed and tokens are now 24 h. Users sign in again; API keys keep working.
4. **Update your API clients for pagination.** `GET /v1/assets` returns at most 200 assets per call — follow `pagination.nextCursor`. Pass `fields=full` if you relied on `description` / `metadata` / `customMetadata` / `publicSettings` being in the list response.
5. **Expect analytics numbers to change.** History is preserved but recomputed from real sessions; previous counts were roughly doubled and watch time was an estimate.
6. **Rename your environment variables**: `DASHBOARD_URL` → `APP_URL` (the old name still works), `STRIPE_PRO_PRICE_ID` → `STRIPE_PRICE_PRO`, `STRIPE_BUSINESS_PRICE_ID` → `STRIPE_PRICE_BUSINESS`.
7. **If you built the per-app images**, switch to the single root `Dockerfile` and set `HOVOD_ROLE=api` / `HOVOD_ROLE=worker`; drop the separate dashboard container, the API serves it.
8. **If you use Cloudflare R2** or a bucket with ACLs disabled, set `S3_PUBLIC_ACL=false` and grant public read on the `playback/` prefix at the bucket level.
9. **Per-rendition `download.mp4` files are no longer produced.** Existing assets keep theirs; new ones get a single `download.mp4` and the download endpoint falls back automatically.
10. Nothing to do about cloud mode: leave `HOVOD_CLOUD` unset and your install stays exactly as unlimited as it was.

## [0.2.0] - 2026-09-04

Reliability hotfix for self-hosters. Upgrade recommended for every install running the all-in-one image.

### Fixed

- **All-in-one image could not restart**: the embedded MariaDB root password was regenerated on every boot. Secrets (`JWT_SECRET`, MariaDB root password) are now generated once and persisted in `/data/.hovod-secrets`; installs whose password no longer matches are repaired automatically at boot.
- **Documented `docker run` quick start crashed** because `JWT_SECRET` was required but never generated.
- **Fresh installs created `jobs` without `current_step`** (an `ALTER TABLE` ran before the `CREATE TABLE`), leaving the first upload stuck in `queued` and the video page returning 500 until a restart.
- **`docker stop` hard-killed MariaDB, Redis and the worker**: the entrypoint no longer `exec`s the API, forwards SIGTERM to every process and exits when a core process dies so `--restart` policies can recover it.
- **Views were counted twice** (a server-side view on every playback metadata fetch plus the player's own). Only the player's `view_start` counts now.
- **Retention curve flat and "avg watched" absurd**: the `current_time` column was parsed by MySQL as the `CURRENT_TIME()` function.
- **10-bit / HDR / ProRes sources failed to transcode** (`FFmpeg exited with code 234`): output pixel format is now forced to `yuv420p`; streams are mapped explicitly so audio-less sources transcode.
- **FFmpeg thread limit was inert** (`-threads` was placed before `-i` and only configured the decoder).
- **AI subtitles never rendered in the player**: HLS output was uploaded without `Content-Type`; manifests, segments, VTT and images now carry correct MIME types and cache headers.
- **Embedded player never showed subtitles** even when they existed.
- **Blank embed in private browsing**: `localStorage` access is now guarded everywhere, plus a root error boundary.
- **Rate-limit (429) and body-too-large (413) responses surfaced as 500**.
- `/health/ready` returns 503 when the database is unreachable; the image now declares a `HEALTHCHECK`.
- `asset.metadata` was double-encoded when AI options were stored (reported by @leuwenn in #3).
- Poster extraction decoded the whole file (`-ss` was an output option).
- `renditions.file_size_bytes` widened to `BIGINT` (renditions over 2 GB failed the job).
- FFmpeg scratch files now live under the persistent volume (`/data/tmp`) instead of the container's overlay filesystem.

## [0.1.0] - 2026-02-13

### Added

- Initial release of Hovod
- REST API with Fastify for asset management (create, upload, import, process, delete)
- BullMQ worker for FFmpeg-based transcoding to adaptive HLS (360p/720p/1080p)
- React dashboard with upload, import, asset management, and video playback
- Embeddable HLS player with quality selector and thumbnail seek preview
- All-in-one Docker image with embedded MariaDB and Redis
- Docker Compose setup for local development
- S3-compatible storage support (AWS S3, Cloudflare R2, Backblaze B2, MinIO)
- Pre-signed URL direct uploads
- URL import from public video URLs
- Thumbnail sprite generation with WebVTT timeline
- Shared Drizzle ORM schemas via `@hovod/db` package
